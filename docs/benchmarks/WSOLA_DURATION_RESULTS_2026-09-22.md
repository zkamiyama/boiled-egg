## Fixes and semantics

Issue62: maintain the integer output limit after every successful push using the
floor of the existing cumulative accepted-input-frame count times the active time
ratio. Enforce that limit in the resampler before EOF as well as after EOF. Flush
retains its existing llround of the accumulated budget. Rejected or unaccepted
input and synthesis padding earn no extra duration. Samples are held before they
are produced, not trimmed from a completed PCM file or retrospectively removed
from a client's buffers. No added output silence or gain fitting is used.

Issue63: during the expanded regression, time4/pitch4 exposed a different existing
stall. The first next_expected position can be smaller than the search radius;
rejecting low_need<0 then prevents every later frame indefinitely. The existing
choose_candidate already clips its search to valid input. Remove that preliminary
rejection while retaining the upper lookahead and actual candidate bounds. This
fix is in a separate commit and affects a previously blocked startup path.

Only engine.cpp/engine.hpp production contents change. No new state fields,
allocation, buffer size, public declaration, ABI/state/ID, default backend,
latency/tail, formant policy, GUI, transport or plugin change. Search scores,
overlap and resampler sample arithmetic are unchanged. Public realtime also uses
the engine, so its existing tests and old-executable comparisons remain required.
Time budget is integrated at accepted-input boundaries; it is not final ratio
multiplied by all earlier input. Dynamic pitch changes can now occur before
previously over-eager output is generated; that observable correction is recorded.
